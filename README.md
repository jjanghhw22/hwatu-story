# 마지막 패 — Phaser 첫 개발 프로젝트

임시 제목. 기존 Unity 프로젝트와 무관한 독립 코드 프로젝트입니다.

## Windows에서 실행
1. Node.js 공식 사이트 https://nodejs.org 에서 LTS를 설치합니다(Node 22.14 이상).
2. ZIP 전체를 압축 해제합니다. Cursor의 File > Open Folder에서 package.json이 있는 hwatu-story 폴더를 엽니다.
3. Cursor 메뉴 Terminal > New Terminal에서 아래 명령을 순서대로 실행합니다.

```sh
npm.cmd install
npm.cmd run dev
```

표시되는 localhost 주소를 브라우저에서 엽니다. index.html 파일을 직접 더블클릭하지 마세요. 종료는 터미널에서 Ctrl+C.
휴대폰: 세로 고정(화면 비율에 맞춰 디자인 높이 1280~1600을 처음 한 번 정함), 회전하거나 창 크기를 바꾸면 새로고침이 필요합니다. 같은 Wi‑Fi에서 보려면 `npx.cmd vite --host 0.0.0.0`으로 띄우고 PC의 LAN 주소를 엽니다.
배포: main에 push하면 GitHub Actions(`.github/workflows/pages.yml`)가 테스트·빌드(`VITE_BASE=/hwatu-story/`) 뒤 GitHub Pages로 자동 배포합니다. 주소 https://jjanghhw22.github.io/hwatu-story/ (저장소 https://github.com/jjanghhw22/hwatu-story). 테스트가 실패하면 배포되지 않습니다.
빌드: `npm.cmd run build`, 테스트: `npm.cmd test`(game, score, scenarios, ai, dialog, character, story/story, story/f2, story/f3, story/f4, story/f5, story/f6, ui/layout, ui/cardAssets, ui/turnPlan). AI 대결 집계: `npm.cmd run match -- 200 1`(판 수, 시드). 카드 그림 재생성: `npm.cmd run split-cards`.

## 이번 버전
- Phaser 3 + TypeScript + Vite.
- 48장 카드 데이터(`src/cards.ts`): 고유 ID, 월, 광/열끗/띠/피, 쌍피, 고도리·홍단·청단·초단, 비광, 국진 플래그. 11월 오동, 12월 비.
- 기본 점수 계산(`src/score.ts`): 화면과 분리된 순수 함수. 국진 선택 상태는 `GameState.gukjinChoice`가 보관. 아래 "점수 규칙" 참고.
- 고/스톱과 승패 판정(`src/game.ts`): 1대1 맞고. 기본 점수 7점부터 고/스톱, 고 횟수별 정산 공식(`settlementPoints`, `src/score.ts`), 스톱 즉시 승리, 마지막 손패 턴의 고 금지, 나가리. 아래 "고/스톱 규칙" 참고.
- 결과창: 승자, 기본 점수, 고 횟수, 정산 점수(또는 나가리)와 "박·특수 규칙 미적용" 표시.
- 모바일 세로형 대결 화면(720×1280 기준 좌표, Phaser Scale.FIT으로 PC는 가운데 배치, 휴대폰은 잘림·가로 스크롤 없음). 일반 모바일 맞고 문법으로 재조립(v0.16): 위에서 아래로 챕터 이름·메뉴(40) → 상대 정보(84: 원형 초상화, 이름, 상태 칩, 오른쪽 끝 점수 배지, 손패 뒷면) → 상대 획득 패(84, 한 줄 4묶음) → 초록 화투판(528: 가운데 뒤집힌 더미 + 더미 둘레 흩뿌림 자리 12개, 같은 월은 겹친 묶음) → 내 정보(64) → 내 획득 패(84) → 내 손패(위 여백 24 + 아랫줄 주 줄 6장 + 윗줄, 105×171, 아래 안전 여백 20). 상시 안내 줄은 없다. 바닥패 자리는 안쪽 고리 6자리부터 채우고 월별 자리를 턴이 지나도 유지해 기존 묶음이 움직이지 않는다(`floorLayout`의 `prevSlots`, 자리 좌표·기울기는 `FLOOR_SLOTS`). 국진·고/스톱·결과·메뉴 모달은 화면 가운데에 큰 버튼으로 표시하고 뒤쪽 입력을 차단한다.
- 실제 화투 그림: `hwatu-overview.svg`(Marcus Richert, CC BY-SA 4.0)에서 `tools/split-cards.mjs`로 48장을 `public/assets/cards/card-00~47.png`(310×505)로 분리하고 카드 ID에 내용 기준으로 연결(원본은 일본식 11월 비·12월 오동 순서라 서로 바꿔 연결). 손패·바닥패·획득패·다음 패 보기·국진 선택창·카드 목록이 같은 연결 정보(`src/ui/cardAssets.ts`)를 쓴다. 상대 손패와 더미는 붉은 뒷면(`back.png`). 출처와 변환 내용은 `THIRD_PARTY_NOTICES.md`와 메뉴 > 제작자·출처 화면에 표시한다.
- 카드 연출(`src/ui/fx.ts`, 설정값은 `FX` 한곳): 아래 "연출·피드백" 절 참고. 턴은 `runPlayerTurn`/`runOpponentTurn` 하나의 비동기 흐름이며 연출이 끝난 뒤 `applyTurn`을 한 번만 호출한다. 연출 중에는 단계가 busy라 입력을 받지 않고, 세대 번호(gen)로 새 판·씬 종료·판 종료 후 남은 연출을 무효화한다.
- 효과음(`src/ui/sound.ts`): 외부 음원 없이 WebAudio로 합성한 짧은 타격음. 패 내기 "착"(2.5~3.5kHz 대역 잡음, 1.5ms 어택 뒤 30ms 안에 감쇠, 저음 없음), 더미 뒤집기 "탁"(같은 질감, 더 작고 짧게), 획득 "차락"(같은 질감 타격 두 번, 내기보다 작게), 손패 선택 "틱"(아주 작게), 따닥(내기 타격 두 번, 따닥 턴에서는 더미 착지음을 대신해 같은 접촉음이 겹치지 않음), 폭탄(타격 세 번), 족보 완성(높은 대역 타격 두 번). 멜로디·전자음·종소리·저음·잔향 없음. 새로 추가한 음색은 직접 듣고 확인하지 않았다. 마스터에 7kHz 저역 통과 필터와 압축기를 두고, 같은 소리는 60ms 안에 중복 재생하지 않아 여러 장 획득 시 커지지 않는다. 재생 시점은 바닥에 닿는 순간·뒤집기가 끝난 순간·획득 칸 도착 순간. 첫 터치 뒤 활성화되며 메뉴의 소리 켜기/끄기 설정을 localStorage에 기억한다. 합성음이라 실제 화투 녹음과는 차이가 있다.
- 메뉴: 새 판 시작, 소리 켜기/끄기(음성도 함께), 연출 줄이기 켜기/끄기(localStorage에 저장. 화면 흔들림·충격 고리·섬광·궤적 없음, 카드 이동·강조 시간 절반, 배너 60%. 필수 선택(바닥패·국진·고/스톱)과 규칙 처리 순서·결과는 같다), 규칙 안내, 제작자·출처, 개발 정보(빌드 표식·미구현 목록·카드 목록·시나리오).
- 화면 모듈 분리(`src/ui/`): `layout.ts`(영역·카드 크기·손패/바닥패 배치, 순수 함수), `widgets.ts`(글자·버튼·막), `cardView.ts`(임시 카드 앞면/뒷면/미니, 이미지 교체 지점), `panels.ts`(초상화·정보·획득 패), `table.ts`(화투판), `modals.ts`(모달), `cardAssets.ts`(그림 연결·preload), `gallery.ts`(개발용 카드 목록), `fx.ts`(이동·뒤집기·강조 연출), `sound.ts`(합성 효과음), `turnPlan.ts`(연출 계획용 순수 함수: place()가 가져갈 카드 미리 계산, 테스트로 place()와 일치 검증). `main.ts`는 턴 흐름과 화면 조립만 담당한다.
- 10/10/8/20 분배, 클릭 또는 터치로 내기, 같은 월 패 획득, 바닥 두 장 중 선택.
- 컴퓨터 상대(`src/ai.ts` 전략 판단, `src/beginner.ts` 첫 상대용 초보 정책, 아래 "컴퓨터 판단" 절), 기술 버튼(눈썰미: 집중력 20으로 더미 윗장 1장 보기, 판당 2회 — 예전 "다음 패 보기 1회"를 대체), 상대 대사(`src/dialog.ts`).
- 획득 패 패널(양쪽 같은 기준, `capturedRects`): 한 줄 4묶음(광·열끗·띠·피, 폭 비율 0.18/0.26/0.26/0.30, 간격 12), 분류 글자 없음. 묶음 안 카드는 높이 64의 세로로 겹친 더미(가로 비낌 14, 폭이 모자라면 최소 4까지 줄이되 크기는 유지), 열끗은 고도리 패를 앞에, 띠는 홍단·청단·초단·비띠 순으로, 피는 쌍피를 앞에 모은다. 묶음 오른쪽 아래 검은 원 배지에 장수(피는 가치), 0장이면 배지도 카드도 없다. 완성 족보와 "고도리 1장"·"홍단 1장"·"삼광 1장" 힌트(손패·획득패·공개 바닥패만으로 판단)는 묶음 위 금색 작은 글자 한 줄. 박 위험은 `turnPlan.bakWarnings`(규칙 계층 `judgeBak` 호출, 고박 제외)로 피 묶음에 "피박", 광 묶음에 "광박"을 빨간 글자로 상시 표시(양쪽 패널 같은 규칙). 내 차례의 안정된 상태에서 패널을 누르면 큰 카드 목록을 연다(흐름에 영향 없음).
- 패 나누기 연출: 무작위 판에서 "첫 판 시작"을 누르면 'dealing' 단계로 들어가 이미 정해진 분배 결과를 더미에서 상대 5 → 나 5 → 바닥 4 → 상대 5 → 나 5 → 바닥 4 순(`turnPlan.dealOrder`)으로 날려 보여준다(한 장 140ms, 출발 간격 45ms, 연출 줄이기에서는 절반). 나·바닥 패는 도착 뒤 앞면으로 뒤집는다. 시나리오 판은 연출 없이 바로 시작.
- 먹을 수 있는 손패 표시: 내 차례에 `GameState.matches`로 바닥에 같은 월이 있는 손패 위에 파란 아래 방향 화살표(폭 26·높이 18, 흰 테두리)를 띄우고 600ms 주기로 위아래 6px 왕복(연출 줄이기에서는 정지). 폭탄·흔들기 배지와 함께 표시된다.

| 최초 선택 조건 | 자기 턴의 모든 획득 처리와 국진 선택이 끝난 뒤, 기본 점수가 7점 이상이면 고/스톱을 묻는다. 6점 이하는 선택 불가. |
| 고 | 고를 선택하면 그때의 기본 점수를 저장한다. 이후 자기 턴 종료 시 기본 점수가 그 값보다 높아졌을 때만 다시 묻는다. 고 보너스로 오른 점수는 재선택 조건이 아니다. |
| 정산 공식 | 0고: 기본 / 1고: 기본+1 / 2고: 기본+2 / 3고 이상: (기본+2) × 2^(고 횟수-2). 예) 기본 10점 → 10 / 11 / 12 / 24 / 48. 화면과 분리된 순수 함수 `settlementPoints`. |
| 스톱 | 선택 즉시 해당 플레이어가 승리한다. 이후 상대 턴이나 예약된 동작은 실행되지 않는다. 결과창에 승자·기본 점수·고 횟수·정산 점수를 표시한다. |
| 마지막 행동 | 남은 행동(손패+뒤집기 기회)이 0이 되는 턴에 조건이 충족되면 고는 불가하고 스톱으로 정산한다. |
| 나가리 | 양쪽 남은 행동(손패+뒤집기 기회)이 모두 소진될 때까지 승자가 없으면 나가리. 기본 점수가 높다는 이유로 승자를 정하지 않으며 다음 판 배수 이월은 없다. |
| 컴퓨터 | 규칙 함수(`canDecide`/`canGo`)가 허용한 경우에만 정책이 판단한다. 첫 상대(이발소 주인, 초보 정책)는 항상 스톱. 전략 정책은 아래 "컴퓨터 판단" 절의 보수적 고/스톱 정책(최대 1고). |
| 초기화 | 새 판에서 고 횟수, 직전 고 점수, 승패, 국진 선택을 모두 초기화한다. 모달 표시 중에는 다른 입력을 받지 않는다. |
| 제외 | 멍박, 보너스 카드는 제외. 결과창에 "멍박·총통·첫뻑·연속뻑 미적용"을 표시한다. |

## 박 규칙과 정산(확정, 구현됨)
| 항목 | 규칙 |
|---|---|
| 피박 | 승자의 피 기본 점수가 1점 이상이고 패자의 피 가치가 1~7이면 ×2. 패자 피 가치 0은 면제, 8 이상은 미적용. 가치는 실제 장수가 아니라 쌍피·국진 선택을 반영한 피 가치. |
| 광박 | 승자의 광 기본 점수가 1점 이상이고 패자의 광 보유 장수가 0이면 ×2. 비광도 패자의 광 보유에 포함. |
| 고박 | 패자가 이번 판에서 고를 1회 이상 선언했고 상대가 스톱(마지막 턴 자동 스톱 포함)으로 승리하면 ×2. 고 횟수와 무관하게 한 번만. |
| 중첩 | 여러 박은 곱한다. 세 가지 모두면 ×8. 나가리에는 박과 정산을 적용하지 않는다. |
| 정산 | 최종 점수 = settlementPoints(기본, 고 횟수) × 박 배수 × 승자 선언(흔들기/폭탄) 배수. 예) 기본 10점, 2고, 피박·광박 → (10+2)×2×2 = 48점. 순수 함수 `judgeBak`, `settle`(`src/score.ts`). |
| 확정 시점 | 스톱 시 `declareStop`이 한 번 계산해 결과(기본 점수, 고 횟수, 고 반영 점수, 박 목록, 박 배수, 최종 점수)에 보관한다. 결과창을 다시 그려도 재계산하지 않는다. |
| 화면 | 결과창: "기본 10점 / 2고 +2점", "피박 ×2 · 광박 ×2"(없으면 "박 없음"), "최종 48점". 나가리는 "나가리". 고/스톱 창에는 지금 스톱할 때의 박 포함 점수를 미리 보여준다. 쪽·뻑·따닥·쓸·뻑 회수는 화투판 가운데에 짧은 배너로 순서대로 표시하고, 뻑 묶음에는 "뻑 · 나/상대" 꼬리표를 붙인다. 상대 피는 상대 획득 칸에서 내 칸으로 날아간다. |

## 쪽·뻑·따닥·쓸과 상대 피 가져오기(1단계 확정, 구현됨)
| 항목 | 규칙 |
|---|---|
| 쪽 | 손패와 같은 월이 바닥에 없어 놓았는데 바로 뒤집은 더미 패가 같은 월이면 두 장 획득. 상대 피 1회. |
| 뻑 | 손패와 같은 월이 바닥에 정확히 1장 있어 맞췄는데 더미 패도 같은 월이면 세 장 모두 바닥에 남긴다(획득·점수 없음). 묶음에 만든 플레이어를 기록한다. 이후 누구든 그 월의 네 번째 패를 내거나 뒤집으면 네 장을 모두 획득. 상대가 만든 뻑을 먹으면 피 1회, 자신이 만든 뻑을 먹으면 피 2회. |
| 따닥 | 턴 시작 시 바닥에 같은 월이 정확히 2장 있고 낸 손패와 더미 패가 모두 그 월이면 4장 획득. 상대 피 1회. 네 장을 모두 가져가므로 선택창을 띄우지 않는다(더미 윗장이 같은 월이면 선택을 묻지 않음). |
| 쓸 | 턴의 모든 획득을 확정한 결과 바닥이 0장이고, 그 턴에 실제로 바닥패를 획득했을 때. 턴 시작부터 빈 바닥이었거나 양쪽 남은 행동(손패+뒤집기 기회)이 모두 소진되는 마지막 턴이면 제외(코드 `lastTurn`, 테스트 동일 기준). 상대 피 1회. |
| 마지막 행동 예외 | 행동한 사람의 마지막 행동(이 행동 뒤 자기 남은 행동 0)에서는 쪽 모양이어도 보너스 없이 두 장만 가져가고, 뻑 모양이면 세 장을 바닥에 남기지 않고 모두 가져간다(뻑 기록 없음). 상대에게 행동이 얼마나 남았든 무관하다(내 남은 행동 1, 상대 2 이상이어도 적용). 기회 패만 쓰는 턴은 손패를 내지 않으므로 마지막 기회든 아니든 쪽·새 뻑 판정 자체가 없다. 공식 설명의 마지막 턴 예외를 따른다. |
| 처음 깔린 3장 | 뻑이 아닌 소유자 없는 일반 묶음. 네 번째 패로 4장을 획득하지만 뻑 회수 보너스는 없다. |
| 합산 | 같은 턴에 별개 조건이 성립하면 보너스를 합산한다(예: 따닥+쓸 = 피 2회). 쪽·뻑·따닥은 같은 패 조합에 중복 판정하지 않는다. |
| 상대 피 가져오기 | 1회마다 상대의 피 카드 한 장을 옮긴다. 일반 피(가치 1)를 id 순으로 우선, 없으면 쌍피·쌍피로 쓰는 국진(가치 2)을 id 순으로. 피가 없으면 가져오지 않고 빚도 남기지 않는다. 여러 회면 매번 남은 패에서 다시 고른다. 복제·분할 없음. |
| 국진 이동 | 국진은 쌍피로 결정된 경우에만 대상이며, 이동해도 이 판의 결정(`gukjinDecision`)을 따르고 새 소유자에게 다시 묻지 않는다. |
| 턴 종료 순서 | 패 획득 확정 → 필요한 국진 선택 → 상대 피 이동 → 양쪽 점수 갱신 → 고/스톱 또는 마지막 턴 처리. 고/스톱 7점 기준, 고 가산·배수, 피박·광박·고박은 피 이동 후의 최종 상태로 판단한다. |
| 제외 | 첫뻑 보상, 연속뻑, 3뻑 자동 패배, 총통(첫 배분 같은 월 4장), 멍박. |

## 흔들기(확정, 구현됨)
| 항목 | 규칙 |
|---|---|
| 선언 조건 | 자기 턴 시작 시 손패에 같은 월이 정확히 3장 있고 아직 그 월로 흔들지 않았을 때. 같은 월 4장은 제외. 손패를 내기 전, 선택이나 연출 중이 아닐 때만. |
| 선언 | 프로젝트 조작 방식: 별도 버튼 없이, 흔들기 가능한 월(손패 정확히 3장, 바닥에 그 월 0장, 아직 선언 안 함)의 카드를 누르면 자동으로 세 장을 공개한 뒤 누른 카드 한 장을 낸다. 공개는 카드를 소비하거나 턴을 넘기지 않으며 턴 번호도 늘지 않는다. 같은 월은 한 판에 한 번, 다른 월은 각각 가능. 폭탄 가능한 월은 폭탄이 우선이라 한 클릭에 둘이 겹치지 않는다. 같은 월 4장은 둘 다 아니다. |
| 배수 | 승자가 선언한 흔들기만 적용. 월마다 ×2(2의 월 수 제곱). 같은 월로 폭탄까지 쓰면 그 월은 한 번만. 패자의 흔들기는 무시. 계산 순서는 고 공식 → 박 배수 → 승자 선언 배수. 예) 기본 10점·2고·피박·흔들기 1회 = 12×2×2 = 48점. 나가리에는 적용하지 않는다. |
| 화면 | 흔들기 가능한 월의 손패에 금색 "흔들기" 표시(폭탄 가능한 월은 주황 "폭탄"이 우선). 누르면 세 장을 가운데로 모아 "흔들기!" 배너와 함께 짧게 공개한 뒤 되돌리고, 이어서 그 카드를 내고 더미를 처리한다(끊김 없음). 공개 중에는 입력을 막는다. 정보 패널에 선언 요약, 고/스톱 미리보기와 결과창에 선언 배수 표시. 새 판에서 기록 초기화. |
| 컴퓨터 | 사람과 같은 규칙: 고른 카드의 월이 흔들기 대상일 때만 그 월을 공개한 뒤 그 장을 낸다. 관련 없는 월을 턴 시작에 모두 흔드는 동작은 없앴다. 더미·상대 손패는 보지 않는다. |
| 상태 검증 | `GameState.version`이 상태를 바꾸는 모든 처리(턴 적용, 흔들기, 피 이동, 국진·고·스톱)마다 늘고, 턴 계획은 만든 시점의 버전을 담는다. `applyTurn`은 버전이 다르면(예: 계획 뒤 흔들기 선언) 거부하므로 다시 계획해야 한다. 상대 차례·판 종료 후·같은 월 재선언은 차단. |
| 제외 | 폭탄과의 배수 관계는 아래 "폭탄과 더미만 뒤집기" 표 참고. |

## 폭탄과 더미만 뒤집기(확정, 구현됨)
| 항목 | 규칙 |
|---|---|
| 폭탄 조건 | 자기 턴 손패를 내기 전, 손패에 같은 월이 정확히 3장이고 바닥에 그 월이 정확히 1장. 자동 실행하지 않고 플레이어가 선택한다. 흔든 월도 가능. |
| 처리 | 세 장을 한꺼번에 내 바닥의 한 장과 함께 4장 획득(쪽·뻑·따닥으로 중복 판정하지 않음) → 더미 한 장을 뒤집어 정상 매칭(뻑 회수 등 기존 규칙). 폭탄 자체로 상대 피 1회, 더미까지 처리한 뒤 바닥이 비면 쓸 보너스 합산. |
| 기회 | 폭탄 1회마다 "손패 없이 더미만 뒤집기" 기회 2회를 카드가 아닌 카운터로 지급. 여러 번 폭탄이면 누적. 이후 자기 턴에 A. 손패 내기 / B. 기회 1회로 더미만 뒤집기 중 선택. 손패가 없으면 기회로만 진행. 더미만 뒤집어도 매칭·획득·뻑 회수·피 이동·점수·고/스톱은 처리하되 손패가 없으므로 쪽·새 뻑·따닥은 없고 쓸은 기존 조건대로. |
| 종료 조건 | 남은 행동 수 = 손패 수 + 뒤집기 기회 수. 손패 0이어도 기회가 남으면 마지막 턴이 아니다. 마지막 턴 고 금지·자동 스톱·양쪽 소진 나가리·마지막 쓸 제외는 모두 남은 행동 수 기준. 48장 보존 검사에 기회 카운터는 포함하지 않는다. |
| 배수 | 폭탄은 해당 월에 ×2 자격. 같은 월로 이미 흔들었다면 추가 ×2 없음. 배수 = 2^(승자가 흔들기 또는 폭탄을 선언한 중복 없는 월 수). 패자 선언 무시. 순서는 고 공식 → 박 배수 → 선언 배수. 예) 기본 10·2고·피박·1월 흔들기 후 1월 폭탄 = 12×2×2 = 48, 다른 월 폭탄 추가 96. 나가리 미적용. 선언 종류와 월은 `shakes`·`bombs`에 따로 기록하고 정산용 `declaredMonths`가 월별로 합친다. |
| 화면 | 별도 버튼 없이, 폭탄 가능한 월의 손패 세 장에 주황 테두리와 "폭탄" 표시가 붙고 그중 아무 장이나 누르면 확인 없이 세 장이 함께 나간다(`actionForTap`). 세 장이 바닥 한 장 위로 이동한 뒤 "폭탄!" 표시. 더미만 뒤집기는 손패 영역 뒤에 붙는 "기회 패"(폭탄 그림·'뒤집기' 글씨, 남은 기회만큼 표시, 화면용이라 카드 데이터·덱·획득패·점수와 무관)를 누른다. 손패는 월순으로 정렬해 표시한다. 정보 패널에 손패 수와 뒤집기 기회를 구분 표시. 고/스톱 미리보기와 결과창에 선언 배수와 근거(월·종류) 표시. |
| 컴퓨터 | 전략 정책은 폭탄 후보(월 오름차순 첫 후보)를 먼저 사용. 초보 정책은 초반에 다른 월의 손패가 있으면 폭탄·흔들기 월을 보유하고, 대안이 없거나 그 월을 고르면 규칙대로 폭탄(세 장) 또는 자동 흔들기를 실행한다. 더미만 뒤집기 기회는 손패 소진 후 사용. 더미·상대 손패를 보지 않는다. |
| 턴 구조 | 규칙 계층의 `TurnPlan.kind`로 일반(normal)·폭탄(bomb)·더미만(flip) 턴을 구분한다(`planTurn`/`planBomb`/`planFlip`). 계획 → 연출 → `applyTurn` 한 번 구조와 판 ID·턴 번호·상태 버전 검증, 획득 → 국진 → 피 이동 → 점수 → 고/스톱 순서를 유지한다. 새 판에서 폭탄 기록·기회·연출 상태 초기화. |

## 조작 방식 요약(프로젝트 기준)
내 차례에 누르는 것 하나로 행동이 정해진다. 일반 손패를 누르면 ① 그 월이 폭탄 가능이면 폭탄 ② 아니면 흔들기 가능하고 아직 선언하지 않은 월이면 자동 흔들기 공개 뒤 그 카드 한 장 내기 ③ 그 외 한 장 내기(`actionForTap`). 손패 영역 뒤의 붉은 기회 패를 누르면 더미만 뒤집기. 먹을 수 있는 손패에는 파란 화살표가 떠 있고, 바닥 두 장 중 고를 때는 그 월만 펼쳐지고 나머지는 어두워진다. 별도 버튼은 내 정보 패널 아래 기술 줄의 기술 버튼(눈썰미·태연한 얼굴, 배운 뒤에만 있고 집중력·횟수가 모자라면 비활성)과 가방(사탕) 버튼, 그리고 "메뉴"뿐이다. 새 판은 지도·이야기 씬에서 시작해 패 나누기 연출을 거쳐 내 차례(선 배지)로 시작한다. 선언으로 상태 버전이 바뀌므로 일반 턴 계획은 공개 연출이 끝난 뒤 만들고, 연출을 기다린 뒤에는 세대 번호·판·턴·버전을 확인한다.

## 컴퓨터 판단(AI)
판단은 `src/ai.ts`(전략)와 `src/beginner.ts`(첫 상대용 초보)의 순수 함수가 하고, Phaser·GameState를 받지 않는다. 입력은 `AiView`(`publicView`로 복사): 자기 손패, 공개된 바닥패, 양쪽 획득패, 국진 결정, 고 횟수, 양쪽 뒤집기 기회 수, 상대 손패 장수, 더미 장수, 뻑 묶음, 자기 흔들기 기록. 상대 손패 내용과 더미의 내용·순서는 들어 있지 않다(테스트: 공개 정보가 같고 사용자 손패·더미 순서만 다른 두 상태에서 같은 판단). `planTurn`은 더미 윗장을 보므로 후보를 `planTurn`으로 돌려 보지 않으며, 행동을 정한 뒤에만 기존 턴 실행기(`runTurn` → 계획 → 연출 → `applyTurn`)가 실행한다. 판단 중 상태를 바꾸지 않는다(테스트). 판 ID·턴·version 검증, 세대 번호, 중복 입력 차단은 그대로다. 판단 이유는 브라우저 콘솔 debug 로그(`[AI 손패] …`)로 볼 수 있다. AI 판단용 난수(`seededRng`, 판마다 새 시드)는 덱 셔플용 난수(`newDeck`의 `Math.random`)와 분리돼 있고 테스트에서는 고정 시드를 주입한다. 패 배분·더미 순서를 조작하거나 플레이어 승리를 강제하지 않는다.

### 전략 정책(이후 상대용, `STRATEGIC`)
| 항목 | 기준 |
|---|---|
| 손패 선택 | 합법 후보(같은 월 바닥 2장이면 바닥패별로)를 모두 평가해 가치가 가장 큰 행동. 동점은 카드 id·바닥패 id 오름차순(재현 가능). 가중치는 `AI_WEIGHTS` 한곳. |
| 획득 가치 | 즉시 오르는 기본 점수(1점 = 10) + 카드 자체 가치(광 3, 열끗 1.6, 띠 1.4, 피 가치 1당 1, 비광 −0.6) + 조합 진행(고도리·홍단·청단·초단·삼광: 조합 점수 × (보유/필요)², 상대가 필요한 패를 가졌으면 0) + 상대 조합 저지(상대 진행 가치 감소분 × 0.8) + 피박 완화(내 피 가치 1~7 구간을 벗어나는 정도 × 6 × 상대 피 압박) + 광박 완화(광 0→1장, 6 × 상대 광 압박) + 뻑 회수(상대 피 1장당 4) + 쓸 가능성(2, 더미 결과에 따라 다르므로 작게). 고정 순위(무조건 광 우선)는 쓰지 않는다. |
| 내려놓기 | 먹을 패가 없으면 (내가 잃는 가치 × 0.7 + 상대가 가져갈 때의 가치 × 0.9)가 가장 작은 패. 같은 월을 더 들고 있으면 절반으로 보고 1.5 보너스(나중에 내가 되찾을 수 있음). |
| 바닥패 선택 | 같은 월 2장 중 위 획득 가치가 큰 쪽. 손패 단계에서는 더미를 보지 않고, 더미가 공개된 뒤의 선택에서는 공개된 그 카드로 판단. |
| 국진 | 열끗/쌍피 각각 기본 점수·카드 가치·조합·피박 위험을 비교, 같으면 열끗. 이미 결정된 판은 `pendingGukjin`이 막아 다시 묻지 않음. |
| 고/스톱(`AI_GO_POLICY`) | 마지막 행동이면 자동 스톱(규칙). 이미 1고면 스톱. 상대 기본 점수 5점 이상이면 스톱. 내 남은 행동 2회 미만이면 스톱. 그 외에는 손패와 현재 바닥패 조합으로 다음 행동에서 기본 점수가 오를 '가능성'이 있을 때만 1회 고(더미 결과에 따라 뻑 등으로 달라질 수 있음을 로그에 명시). 바닥에 맞는 패가 없으면 더미 운에만 기대는 것이라 스톱. 임계값은 한곳에 모아 상대별 성격으로 바꿀 수 있다. |
| 폭탄·흔들기 | 폭탄 가능 월이 있으면 폭탄 우선. 고른 카드의 월이 흔들기 대상이면 공개 뒤 그 장을 낸다. |

### 단순화된 부분(AI)
- 더미 확률(남은 카드 분포로 쪽·뻑 확률 계산)을 쓰지 않는다. 쓸·고 판단의 '가능성'은 손패와 바닥패 조합만 본다.
- 조합 진행 가치는 (보유/필요)² 한 가지 곡선이고, 열끗 5장·띠 5장·피 10장 진행은 카드 자체 가치(선형)로만 반영한다.
- 상대 손패 추정, 여러 턴 앞 읽기, 상대의 고 횟수·선언 배수에 따른 위험 가중은 없다. 고박 위험(내가 고한 뒤 상대가 이김)은 고/스톱 정책의 상대 점수 임계값으로만 다룬다.
- 뻑 회수 가치는 상대 피 유무만 본다. 초보 정책의 바닥패·국진 선택은 전략 정책을 그대로 쓴다.

### 턴 처리 구조
`GameState.analyzeHand`가 손패의 선택 필요 여부를 알려주고, `planTurn(player, card, handTarget?, deckTarget?)`이 손패와 더미 윗장을 함께 판정한 계획(`TurnPlan`: 놓기 동작, 획득 묶음, 바닥에 남는 패, 이벤트, 피 가져오기 횟수, 뻑 생성·회수, 더미 패 선택 필요 여부)을 돌려준다. 상태는 바꾸지 않는다. 화면은 이 계획대로만 연출하고, 끝난 뒤 `applyTurn`(한 번)과 `stealPi`를 호출한다. 계획에는 판 ID·턴 번호·적용 여부가 들어 있어 `applyTurn`은 현재 판·턴과 일치하고 아직 적용하지 않은 계획만 받으며(더미 윗장 검사 포함), 어긋나면 상태를 바꾸지 않고 거부한다. 더미 패는 뒤집기 연출 전까지 앞면을 보이지 않는다. 개발용 시나리오(`src/scenarios.ts`, 메뉴 > 시나리오)는 고정 패 구성으로 쪽·뻑·상대 뻑 회수·따닥·두 장 선택·쓸·따닥+쓸·처음 3장·흔들기·폭탄·폭탄 우선과 자동 흔들기·손패 없이 기회만 남음·빈 바닥·족보 완성(고도리, 획득패 지정 `captured0`)·국진 선택·고/스톱(결과창까지)을 재현하며 무작위 배분과 분리돼 있다.
상태 동작 추가(규칙 변경 아님, v0.21~0.23): `GameState.forfeit(loser, { minBase?, kind? })` 합의 종료 — `kind` 'bust'(들통)·'caught'(잡기)는 승자 기본 점수 max(기본, 7)에 고 공식, 'fold'(접기)는 승자 기본 점수 그대로(최소 없음·고 공식 없음). 모두 박·선언 배수 없음, 결과에 `forfeit: true`와 `endKind`. `GameState.swapHandWithDeck(player, cardId)` 바꿔치기 — 자기 차례에 손패 한 장과 더미 윗장을 맞바꾼다(순수 배열 교환, 48장 보존, version+1, 상대 차례·빈 더미·끝난 판은 거부). 성공 확률·의심도·미션 배수는 story 계층이 정하고 규칙 결과에는 들어가지 않는다.

## 명확한 한계
완성된 맞고가 아닙니다. 고/스톱과 승패(스톱 승리·나가리), 피박·광박·고박 정산, 쪽·뻑·따닥·쓸과 상대 피 가져오기, 흔들기, 폭탄과 더미만 뒤집기는 구현됐지만 멍박, 총통/재분배, 첫뻑·연속뻑·3뻑은 미구현입니다. 첫 상대(이발소 주인)는 초보 정책이라 고/스톱 가능 시 항상 스톱하며, 전략 정책은 이후 상대용으로만 준비돼 있습니다. 저장, 결제, 앱 패키징, 음원은 없습니다. 이번 연출 개선(접촉·뒤집기·손패 정리·획득 패널 재배치·족보 표시·점수 강조·말풍선·결과창 순차 표시·연출 줄이기)과 비주얼 개편(나무·황동·천 테마, 붓글씨 배너, 초상화 컴포넌트, 로컬 폰트), 새 효과음은 아직 실제 브라우저·휴대폰에서 보거나 듣지 않았습니다(테스트·빌드만 통과). 캐릭터 그림은 두 인물의 기본 표정 한 장씩만 있어 작은 원형 초상화에만 쓰고(실제 화면 미확인), 표정 그림·음성 파일은 없습니다. 스토리 뼈대(v0.19)는 소유자가 헤드리스로 1장까지 확인했고, F2(v0.20)는 소유자가 헤드리스로 시장 해금까지 확인했고, F3-시스템(v0.21)은 소유자가 헤드리스로 확인했고, F3-장(v0.22)은 소유자가 헤드리스로 확인했고, F4(v0.23)는 소유자가 헤드리스로 확인했고, F5(v0.24: 기술 두 줄·접기 가르치기 보정·10장 문지기 셋·부적·관계 분기·11장 3단계·판돈 ×2·엔딩 3종·에필로그·크레딧·장 바로가기)는 소유자가 자동 완주(엔딩 A·B·C)로 확인했고, 완주 보정(v0.25: 입장 ×3·태오 대납·안전망·10장 ▶ 안내·밤 경과·영화표 조건 10·크레딧 문구)은 테스트·빌드만 통과했고 실제 화면은 보지 않았습니다. 손바꿈·기억력, 도시락, 서린 사건 2개는 데이터만 있고 동작하지 않습니다. 컷 그림과 장대식·한도윤 외 인물 그림은 없습니다(글자 컷·자리 표시 초상화). 기본 화면 재조립(v0.16: 손패 6+4 두 줄, 획득 패 한 줄 4묶음·장수 배지·박 경고, 바닥 12자리 흩뿌림·기울기, 점수 배지·상태 칩·선 배지, 패 나누기 연출, 먹을 수 있는 패 화살표)도 테스트·빌드만 통과했고 실제 화면은 보지 않았습니다. 이전 배치와 효과음은 PC에서 한 차례 확인됐습니다.
