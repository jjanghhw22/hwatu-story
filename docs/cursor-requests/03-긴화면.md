# Cursor 요청 03 — 긴 휴대폰 화면 대응 + 보정 2건

v0.17을 헤드리스 브라우저(720×1280)로 다시 돌려 요청 02의 7개 항목이 모두 고쳐진 것을 확인했습니다(더미 45→20 카운트다운, 펼침 방향, 말풍선·배지, "+N" 위치, 들고 있는 카드, 빈 패널). 이번 요청은 실제 휴대폰에서 가장 먼저 눈에 띌 "위아래 검은 띠" 문제와, 확인 중 발견한 작은 문제 2건입니다. 요청 01의 "0. 공통 제약"을 그대로 적용합니다.

## 1. 긴 화면 대응 (우선)
현상: 디자인 좌표가 720×1280(9:16)으로 고정돼 있어 1080×2340(9:19.5) 같은 요즘 휴대폰에서는 Scale.FIT이 폭에 맞추고 위아래에 약 210px씩 검은 띠가 남는다. 기준작(고스톱대전)은 화면을 꽉 채운다.
기대:
1. 디자인 폭 720은 고정, 디자인 높이를 기기 비율에 맞춰 **1280~1600 사이로 가변**으로 한다. `startGame()`에서 `window.innerWidth/innerHeight`로 `h = clamp(1280, round(720 × innerH / innerW), 1600)`을 계산해 `Phaser.Game`의 height로 넘기고, Scale.FIT + CENTER_BOTH는 그대로 둔다(비율이 더 긴 기기에서만 남는 띠는 허용). 가로 모드(innerW > innerH)는 1280으로 둔다.
2. layout.ts의 `DESIGN.height`와 `REGIONS`를 상수에서 **`configureLayout(height)` 함수로 재계산되는 값**으로 바꾼다. `REGIONS` 객체는 export 이름과 필드명을 유지하고(28곳에서 참조) 내부 값만 갱신한다. 모듈 로드 시 `configureLayout(1280)`을 한 번 호출해 테스트와 기존 호출이 지금과 같은 값을 보게 한다. `startGame()`은 Phaser.Game을 만들기 **전에** `configureLayout(h)`를 호출한다.
3. 늘어난 높이(h − 1280)의 배분: 먼저 **안전 여백**(아래 4번) → 남는 양의 70%를 화투판(TABLE_H)에, 30%를 손패 위 여백(HAND_TOP_PAD)에 더한다. 화투판이 커지면 바닥 카드 크기 상한(130)은 그대로 두고 FLOOR_SLOTS 간격만 비례해 넓어진다(scale 계산이 이미 tableInner 기준이면 그대로). 손패·획득패·정보 패널 크기는 바꾸지 않는다.
4. 안전 여백: index.html에 `viewport-fit=cover`가 있으므로 노치·홈바 영역이 캔버스에 겹칠 수 있다. `startGame()`에서 보이지 않는 probe 요소에 `padding-top: env(safe-area-inset-top)` / `padding-bottom: env(safe-area-inset-bottom)`을 주고 `getComputedStyle`로 픽셀값을 읽어 디자인 단위(× 720 / innerW)로 바꾼 뒤 `configureLayout(h, {top, bottom})`에 넘긴다. top은 상단 띠(TOP_H) 위에, bottom은 BOTTOM_SAFE에 더한다. 값을 못 읽으면 0.
5. 회전·창 크기 변경: 처음 한 번만 계산한다. `resize` 이벤트에서 비율이 10% 이상 달라지면 콘솔 debug 로그만 남기고 다시 계산하지 않는다(판 중간에 배치를 바꾸지 않기 위해). README에 "회전 시 새로고침 필요"로 적는다.
6. 테스트(layout.test.ts): `configureLayout(1280)`이 기존 값과 같음 / `configureLayout(1600)`에서 영역이 위에서 아래로 겹치지 않고 1600 안에 들어가며 table.h ≥ 528 / `configureLayout(1560, {top: 40, bottom: 30})`에서 topBar.y ≥ 40, 손패 아래 여백 ≥ 50 / 손패·획득패·정보 패널 높이는 높이와 무관하게 동일. 테스트 파일 맨 앞에서 `configureLayout(1280)`을 호출해 다른 테스트에 영향이 없게 한다.

## 2. 아랫줄 화살표가 윗줄 카드 뒤에 숨는다
현상: 손패가 7장 이상이면 아랫줄 카드의 파란 화살표가 윗줄 카드 아래에 그려져 꼭짓점만 삐죽 보인다(화살표를 카드와 같은 순서로 그리기 때문).
기대: 화살표는 손패 카드를 **모두 그린 뒤** 별도 패스에서 그려 항상 맨 위에 오게 한다(main.ts draw()의 손패 블록 끝에서 화살표 목록을 모아 한 번에 그림). 트윈 정리 방식은 그대로. 아랫줄 화살표가 윗줄 카드와 겹치는 것 자체는 허용(맨 위에만 있으면 된다).

## 3. 국진 선택창의 빈 공간
현상: 국진 모달에서 제목과 본문 사이가 카드 높이만큼 비어 있고 본문 글자가 카드 아래로 밀려 있다(카드 오른쪽 공간을 쓰지 않음).
기대: modals.ts drawModal에서 card가 있을 때 본문 글자를 카드 **왼쪽 옆**에 textW 폭으로 배치하고(이미 textW 계산은 있음), 본문 시작 y를 제목 바로 아래로 둔다. 본문 높이와 카드 높이 중 큰 쪽 아래에 버튼을 둔다. 다른 모달(고/스톱·결과·메뉴)은 바뀌지 않아야 한다.
