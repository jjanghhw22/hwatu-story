# Cursor 요청 12 — 화투 카드 그림 교체(골목간판풍) + 칩 겹침 보정

소유자가 만든 '골목간판풍' 화투 48장으로 카드 그림을 바꿉니다. **그림 파일은 이미 교체해 두었습니다**(Claude가 변환): `public/assets/cards/card-00.png`~`card-47.png`(각 400×600, 256색, 평균 64KB, 합계 3.1MB), 새 뒷면 `back.png`(같은 테두리 + 매화 문양), `cards.json`(새 출처 정보). 변환 방법은 `tools/prepare-cards.py`에 있습니다.
원본 파일 번호 n(01~48)이 카드 id n−1에 그대로 대응합니다(src/cards.ts 슬롯 순서와 같음 — 1월 광·홍단·피·피 … 11월 광·쌍피·피·피, 12월 비광·제비·비띠·비쌍피). 클라우드에서 이 파일들과 아래 1번 변경만으로 빌드해 대결 화면(휴대폰·PC 비율)에서 정상 표시를 확인했습니다.
공통 제약은 이전과 같습니다(규칙 계층 수정 금지).

## 1. 카드 비율 2:3
- `src/ui/cardAssets.ts`와 `src/ui/layout.ts`의 `CARD_ASPECT = 103.2 / 168.2` → `2 / 3`. 주석도 "골목간판풍 카드 400×600(2:3)"으로.
- 이 변경으로 1280 화면에서 손패가 조금 넓어지고 화투판이 464 → 488로 커집니다. `layout.test.ts`의 1280 기준값(긴 화면 테스트의 table.h 등)을 새 값으로 갱신하되, "영역 비겹침·화면 안·바닥 12자리 비겹침" 같은 의도 검사는 그대로 통과해야 합니다.

## 2. 카드 연결표 테스트 갱신
- `src/ui/cardAssets.test.ts`의 "cards.json 연결표…" 테스트는 옛 위키미디어 원본(일본식 배열·행/열 좌표)을 검사합니다. 새 형식으로 바꿉니다: `frame` 비율이 CARD_ASPECT와 같음 / 48장 / `m.id === (m.month-1)*4 + m.slot` / `m.source.no === m.id + 1` / `m.source.file`이 `골목간판풍_${두 자리 번호}_`로 시작 / 번호 중복 없음. 파일 존재·크기 검사는 그대로.

## 3. 원본 압축 파일 이동
- `public/assets/cards/골목간판풍_20_창포피_B.zip`(143MB)은 `public/` 아래에 있으면 로컬 빌드 때마다 dist로 복사됩니다. 저장소 루트의 `art/cards-src/`로 옮기고 `.gitignore`에 `art/cards-src/*.zip`(또는 `art/`)을 두세요. 기존 `.gitignore`의 해당 줄은 새 경로로.
- `tools/prepare-cards.py`(이번에 추가된 파일)는 커밋합니다. README "카드 그림 재생성" 줄을 `python tools/prepare-cards.py art/cards-src/<압축 푼 폴더> public/assets/cards`로 바꾸고, 기존 `npm run split-cards`(위키미디어 SVG 분할)는 package.json 스크립트에서 빼거나 "옛 도안용"으로 이름을 바꿉니다. `hwatu-overview.svg`·`tools/split-cards.mjs`는 지우지 말고 둡니다.

## 5. 보정 — 내 정보 패널 칩이 기술 줄과 겹친다
현상: 폭탄을 쓴 뒤 내 정보 패널에 "뒤집기 2"·"국진→쌍피" 같은 칩이 생기면 칩이 둘째 줄로 넘어가 **기술 버튼 줄 위쪽과 겹친다**(휴대폰·PC 비율 모두 확인).
기대: 칩은 패널 안에서만 배치. 한 줄에 다 안 들어가면 칩 글자를 줄임말("뒤집기2", "국→쌍")로 바꾸고, 그래도 넘치면 마지막 칩을 "+N"으로 묶는다. layout.test.ts에 "칩 6개(고·흔·폭·뒤집기·국진·뻑)가 내 정보 패널 안에 있고 기술 줄과 겹치지 않음" 추가.
