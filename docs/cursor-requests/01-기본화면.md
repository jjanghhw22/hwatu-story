# Cursor 요청 01 — 기본 대결 화면을 일반 맞고 문법으로 재조립

먼저 README.md, src/main.ts, src/ui/layout.ts, src/ui/panels.ts, src/ui/table.ts, src/ui/fx.ts, src/ui/cardView.ts, src/ui/turnPlan.ts, src/ui/layout.test.ts를 읽고 시작하세요.
이번 작업은 "화면 배치와 연출 흐름을 익숙한 모바일 맞고 방식으로 맞추는 것"입니다. 규칙·점수·AI는 완성 상태이므로 바꾸지 않습니다.

## 0. 공통 제약 (반드시 지킬 것)
- 수정 금지: src/game.ts, src/score.ts, src/cards.ts, src/ai.ts, src/beginner.ts, src/scenarios.ts, src/dialog.ts, src/ui/cardAssets.ts, public/assets/cards/*. 규칙 계층의 함수 시그니처도 바꾸지 마세요.
- 구조 유지: 턴은 "계획(planTurn/planBomb/planFlip) → 연출 → applyTurn 1회 → 국진 → 족보 → stealPi → 점수 강조" 순서 그대로. 세대 번호(gen)·판 ID·턴 번호·version 검증, 모달 중 입력 차단, 연출 줄이기(FxSettings.reduced) 의미도 그대로.
- 화면에서 규칙을 다시 구현하지 마세요. 박 판정은 src/score.ts의 judgeBak, 먹을 수 있는 패는 GameState.matches, 폭탄·흔들기 후보는 bombCandidates/shakeCandidates를 호출합니다.
- 상대 손패 내용과 더미 순서는 화면 판단에 쓰지 않습니다(공개된 바닥패·획득패만).
- 새 그림 파일을 만들거나 요구하지 마세요. 화살표·배지·칩·선 표시는 모두 Phaser 도형과 글자로 그립니다.
- 수치(크기·간격·시간)는 layout.ts와 fx.ts의 FX 한곳에 상수로 두고, 그리기 코드에 숫자를 흩뿌리지 마세요.
- README의 "확정" 규칙표는 수정하지 않습니다. 비주얼·조작 절과 "이번 버전" 목록만 이 작업 내용으로 갱신하세요.

## 1. 손패 (layout.ts handLayout, main.ts draw 8번 블록)
1. 줄 구성을 바꿉니다: 아랫줄이 주 줄이며 최대 6장(HAND_MAIN_ROW = 6), 7장째부터는 윗줄에 왼쪽 정렬로 놓습니다(최대 4장 + 기회 패). 두 줄 모두 완전히 보이게 하고(겹치지 않음), 아랫줄은 가로 가운데 정렬, 윗줄은 아랫줄 첫 장과 왼쪽을 맞춥니다.
2. 카드 크기: 6장이 폭 720 − MARGIN×2 안에 GAP 간격으로 들어가는 높이를 CARD_ASPECT로 계산하고 상한 196. 손패 영역(REGIONS.hand) 높이는 두 줄 + GAP + BOTTOM_SAFE로 다시 계산하세요.
3. 먹을 수 있는 패 표시: phase === 'hand'일 때 state.matches(card).length > 0인 손패 위쪽 가운데에 파란 아래 방향 삼각형(폭 26, 높이 18, 색 0x3b82f6, 흰 테두리 2)을 띄우고 위아래 6px를 600ms 주기로 왕복합니다. 연출 줄이기에서는 움직이지 않습니다. 폭탄·흔들기 배지가 있는 카드는 기존 배지를 유지하고 화살표도 같이 표시합니다. 화살표는 draw()마다 다시 만들어지므로 그 트윈은 SlideTracker.killTweens와 같은 방식으로 목록에 보관해 draw() 시작과 teardown에서 정리하세요.
4. 기회 패(drawChanceCard)는 지금처럼 손패 끝에 두되 윗줄·아랫줄 규칙을 같이 따릅니다. 손패 월순 정렬, 사용한 패 빈자리 미끄러짐(SlideTracker)은 그대로.
5. handRects(player, cards)와 shake()·runTurn()의 출발 좌표가 새 배치와 일치하는지 확인하세요(handDisplay 인덱스 → handLayout 인덱스).

## 2. 획득패 패널 (layout.ts capturedLayout/capturedRects, panels.ts drawCaptured)
1. 두 줄 → 한 줄 4묶음(광·열끗·띠·피, 왼쪽부터). 묶음 폭 비율은 0.18 / 0.26 / 0.26 / 0.30. 분류 글자 라벨("광", "열끗" …)은 없앱니다. 묶음 사이 간격 12.
2. 묶음 안 카드는 세로로 겹친 더미처럼 보이게: 미니 카드 높이 64(CARD.mini 갱신), 가로 비낌 기본 step 14, 묶음 폭이 모자라면 miniStep으로 줄이되 최소 4. 기존 정렬 규칙(capturedOrder: 고도리 먼저, 홍단·청단·초단·비띠 순, 쌍피 먼저)은 유지하고 묶음 사이 틈(groupGap)은 없앱니다.
3. 장수 배지: 각 묶음 오른쪽 아래에 지름 24의 검은 원(0x111111, 알파 0.9) + 흰 숫자(굵게 13). 광·열끗·띠는 장수, 피는 가치(score.피.value, 쌍피·국진 반영). 0장이면 배지도 카드도 없이 빈 자리만.
4. 완성 족보와 힌트: 기존 g.bonuses(고도리·홍단·삼광 등)와 near 힌트("고도리 1장" 등)는 해당 묶음 위에 작은 금색 글자(11px) 한 줄로 유지합니다.
5. 박 위험 표시(신규): src/ui/turnPlan.ts에 순수 함수 bakWarnings(state, player): ('피박'|'광박')[] 를 추가합니다. 구현은 judgeBak(state.score(1 − player), state.score(player), 0)을 호출해 '피박'·'광박'만 걸러 돌려주는 것으로, 규칙을 다시 쓰지 않습니다(고박은 세 번째 인자를 0으로 넘겨 제외). drawCaptured는 이 결과를 받아 피 묶음 왼쪽에 "피박", 광 묶음 왼쪽에 "광박"을 빨간 굵은 글자(0xe03a3a, 18px, 검은 외곽선)로 상시 표시합니다. 양쪽 패널 모두 같은 규칙입니다. turnPlan.test.ts에 피 가치 0·7·8, 광 0·1장, 상대 피 점수 0일 때의 경계 테스트를 추가하세요.
6. 패널 높이는 한 줄 기준으로 84로 줄이고, 줄어든 만큼 화투판(REGIONS.table)을 키웁니다. 최종 REGIONS는 위에서 아래로 겹치지 않고 1280 안에 들어와야 하며(기존 테스트), 목표는 table 높이 500 이상입니다.
7. capturedRect()(연출 도착점)과 drawCaptured의 자리가 같은 capturedRects를 쓰는 구조는 그대로입니다. 결과·획득패 큰 목록(drawCapturedView)은 바꾸지 않습니다.

## 3. 바닥패 (layout.ts floorLayout, table.ts drawTable, cardView.ts, fx.ts)
1. 5×3 격자를 버리고 "더미 둘레 흩뿌림 자리" 12개로 바꿉니다. FLOOR_SLOTS: 더미 중심을 원점으로 한 상대 좌표와 자리별 고정 기울기(−6°~+6°, 자리마다 다른 상수) 배열. 안쪽 고리 6자리(더미에서 가까움), 바깥 고리 6자리. 자리 배정 규칙은 기존 그대로(prevSlots로 기존 월은 같은 자리 유지, 새 월은 배열 앞 순서부터). floorLayout의 반환형(cards, drawOrder, deck, scale, slots)은 유지합니다.
2. 같은 월 묶음은 stackDx 0.3으로 비껴 겹치고, 장마다 기울기를 +3°씩 더합니다. fanMonth(선택 단계)의 펼침 동작은 그대로.
3. Rect에 선택 속성 angle?: number 를 추가합니다. drawCardFace는 r.angle이 있으면 setAngle로 기울이고(원점 중앙 기준으로 위치 보정), fx.fly/moveTo는 도착 시 r.angle ?? 0으로 각도를 복원합니다(지금은 0으로 고정). 손패·획득패는 angle 없이 지금과 같습니다.
4. 바닥 카드 크기: 높이 상한 130. 12자리 + 더미 + 3장 묶음 폭 + 기울기 여유가 tableInner 안에 들어오도록 scale을 계산합니다. 자리끼리, 자리와 더미가 겹치지 않아야 하며 기존 테스트("다른 월·더미와 겹치지 않음")는 회전을 포함한 경계 사각형(bounding box) 기준으로 갱신합니다.
5. 더미: 뒷면 두 장 두께감 유지, 뒷면 위의 "더미 N" 글자는 없애고 더미 오른쪽 아래에 2번과 같은 검은 원 배지로 남은 장수만 표시합니다.
6. 상시 메시지 띠(TABLE_MESSAGE_H)를 없앱니다. this.message는 비어 있지 않을 때만 화투판 위쪽 가운데에 반투명 캡슐(높이 30, 0x000000 알파 0.55, 글자 14)로 띄우며 바닥 자리를 차지하지 않습니다. 결과창·모달의 메시지 사용처는 그대로.
7. holdRect(), newFloorRect(), floorRectOf(), landRect()가 새 배치와 일치하는지 확인하세요. 뻑 꼬리표는 묶음 첫 장 아래 그대로.

## 4. 정보 패널 (panels.ts drawPlayerInfo, layout.ts oppHandLayout)
1. 점수: "N점" 글자를 패널 오른쪽 끝의 큰 배지로 바꿉니다(가로 96, 세로 40, 검은 바탕 0x111111 알파 0.9, 황동 테두리, 금색 굵은 숫자 26 + "점" 14). 상대·나 모두 같은 모양. scorePulse가 이 배지의 숫자 Text를 받도록 scoreText 반환은 유지합니다.
2. 고·흔들기·폭탄·기타 상태는 글자 나열(parts.join) 대신 작은 칩으로 바꿉니다: 둥근 사각형(높이 20, 가로 글자폭+14) 안에 "1고", "흔들기 1", "폭탄 1", "뒤집기 2", "국진→쌍피", "뻑 1". 값이 0인 칩은 그리지 않되 고 칩만은 항상 두고 0이면 흐리게(알파 0.35). 칩 색: 고 0xc0392b, 흔들기 0xb08d4a, 폭탄 0xf0923a, 나머지 0x2b3b36. 글자는 흰색 12.
3. 선(先) 배지: 이 판에서 먼저 시작한 플레이어 이름 왼쪽에 지름 22 붉은 원(0xc0392b)과 흰 글자 "선". 지금은 항상 플레이어 0이 선이므로 PlayerInfo에 first: boolean을 넣어 호출하는 쪽이 넘깁니다. 선 교대 규칙은 이번에 추가하지 않습니다.
4. 상대 패널의 손패 뒷면 줄, 말풍선 자리(speechZone), 활성 패널 금색 테두리, "내 차례"/"상대 차례"/"바닥패 선택" 상자는 그대로. 글자가 배지·칩과 겹치지 않도록 왼쪽(초상화·이름·칩)과 오른쪽(점수 배지, 상대는 그 아래 손패 뒷면) 구역을 나누세요. 기존 테스트 "상대 말풍선 자리는 제목·점수 글자와 겹치지 않는다"를 새 배치로 갱신합니다.
5. 내 패널의 "다음 패 보기" 버튼은 점수 배지 왼쪽으로 옮기고 폭 140으로 줄입니다. 미리보기 카드(CARD.peek) 자리도 같이 옮깁니다.

## 5. 패 나누기 연출 (main.ts, fx.ts)
1. Phase에 'dealing'을 추가합니다. 무작위 판에서 인트로 모달의 "첫 판 시작"을 누르면 'hand' 대신 'dealing'으로 들어갑니다(restart도 create()를 거쳐 인트로로 돌아오므로 같은 경로입니다). 시나리오 판(scenarioKey 있음)은 분배 연출 없이 바로 'hand'.
2. GameState의 분배 자체는 바꾸지 않습니다(이미 생성자에서 끝남). 연출은 "이미 정해진 결과를 보여주는 것"입니다: 시작 시 hands[0], hands[1], table의 모든 카드 id를 this.hidden에 넣고 draw()한 뒤, 더미 자리(lastFloor.deck)에서 출발하는 뒷면 스프라이트를 순서대로 날립니다.
3. 순서는 src/ui/turnPlan.ts의 순수 함수 dealOrder(state): {card, to:'opp'|'me'|'floor'}[] 가 정합니다: 상대 5 → 나 5 → 바닥 4 → 상대 5 → 나 5 → 바닥 4 (각 그룹은 배열 순서대로). turnPlan.test.ts에 28장·그룹 순서·중복 없음 테스트를 추가하세요.
4. 시간은 FX에 추가: deal: 140(한 장 이동), dealStep: 45(다음 장 출발 간격). 연출 줄이기에서는 ms()로 절반. 도착지: 상대는 oppHandLayout의 자리(뒷면 유지), 나는 handLayout의 자리(도착 뒤 flipTo로 앞면), 바닥은 floorLayout의 자리(도착 뒤 flipTo, 자리 기울기 적용). 도착한 카드는 hidden에서 빼고 draw()로 정적 화면에 넣은 뒤 스프라이트를 제거합니다. 효과음은 장마다 'deal'을 호출하고 기존 60ms 중복 차단에 맡깁니다.
5. 모든 await 뒤에 gen을 확인하고, teardown이 분배 중 스프라이트를 정리하도록 fx.clear()에 맡깁니다. 분배 중에는 메뉴 버튼을 비활성(phase !== 'hand' 조건이 이미 막음)으로 두고, 끝나면 phase = 'hand', turnOwner = 0, 메시지 "내 차례입니다. 손패를 누르세요."로 draw()합니다.
6. 폭탄·흔들기 배지, 먹을 수 있는 패 화살표는 'dealing' 중에는 그리지 않고 'hand'부터 그립니다.
