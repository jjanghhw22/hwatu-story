# Cursor 요청 05 — 스토리 뼈대(F1): 데이터 계층 · 여정 지도 · 집중력 · 1장 완성

먼저 `docs/story/시나리오-바이블.md` 전체와 README, src/main.ts, src/character.ts, src/ai.ts(Opponent 인터페이스·BEGINNER), src/dialog.ts, src/ui/modals.ts를 읽으세요.
이번 범위는 바이블의 "구현 순서 F1"입니다: **프롤로그 → 1장(이발소) → 집 해금 → 편의점 노드가 잠긴 채 보이는 데까지** 플레이 가능하게. 2장 이후는 데이터만 넣고 잠급니다.

## 0. 공통 제약
- 규칙 계층(src/game.ts, score.ts, cards.ts, ai.ts의 판단 로직, beginner.ts, scenarios.ts) 수정 금지. 대결 화면(TableScene)의 계획→연출→applyTurn 구조·테스트 유지.
- 그림 파일을 새로 만들거나 요구하지 않는다. 컷·지도·아이콘은 도형과 글자로 그리되, **그림 경로를 데이터에 적어 두고 파일이 있으면 그림, 없으면 글자 컷**으로 표시한다(초상화 preload와 같은 방식). 나중에 그림만 넣으면 되게.
- 이야기 데이터는 코드에 **데이터로** 둔다(함수 안에 문자열을 흩뿌리지 않는다). 대사·이름·수치는 바이블의 것을 그대로 쓴다.
- 새 모듈은 `src/story/`(데이터·진행), `src/scenes/`(여정·이야기 씬)에 둔다. main.ts의 TableScene은 `src/scenes/table.ts`로 옮겨도 되지만 이번에 옮기지 않아도 된다(옮기면 import만 바꾸고 내용은 그대로).

## 1. 데이터 계층 (src/story/)
1. `characters` 확장(src/character.ts): 이름을 바이블대로 — 플레이어 '한도윤', 이발소 주인 '장대식'. 나머지 인물(윤서린, 마철수, 오복희, 문태오, 강봉구, 조상철, 민정호, 차유라, 구상만, 백무진, 한기석)을 id·이름·별명·초상화 경로(`assets/characters/<id>-neutral.png`, 없어도 됨)로 추가. 기존 portraitFit 구조 유지.
2. `src/story/chapters.ts`: 바이블 5절의 프롤로그·1~11장·에필로그를 `Chapter { id, title, place, unlocks, opponentId?, rewardSkill?, scenes: { before: Scene[], after: Scene[] } }`로. Scene은 `{ kind: 'cut', image?: string, text: string }` 또는 `{ kind: 'line', speaker: characterId, text: string }`. **프롤로그와 1장은 바이블 대사로 전부 채우고**, 2장 이후는 제목·장소·상대·보상·잠금 조건만(대사는 한두 줄 placeholder).
3. `src/story/opponents.ts`: 상대 프로필 `OpponentProfile { id, characterId, policy: 'beginner'|'strategic', focusMax?, taunt?: …, thinkMs }`. 1장 장대식 = beginner. 다른 상대는 strategic + 바이블 6절의 성격 키워드만 필드로 적어 두고(도발·역정보·속공·봉쇄 등) 이번에 동작은 구현하지 않는다.
4. `src/story/skills.ts`: 바이블 3절 기술 8개를 `{ id, name, cost, suspicion, kind: 'honest'|'cheat', desc, usesPerMatch }`로. 이번에 **동작하는 것은 눈썰미 하나**(아래 3절).
5. `src/story/items.ts`: 7절 아이템 10개 데이터(효과는 설명 문자열 + 수치 필드). 동작은 다음 단계.
6. `src/story/progress.ts`: 진행 상태와 저장. `Progress { day, money, chapterId, unlockedPlaces, skills: string[], focusMax, focus, flags: Record<string, boolean> }`. 시작값: day 1, money 120000, chapter 'prologue', places ['home'?]… (집은 1장 끝에 열리므로 시작은 ['barber']), focusMax 100. localStorage 키 `hwatu.progress.v1`, 저장 실패는 무시. `resetProgress()` 제공(메뉴 > 개발 정보에 "진행 초기화" 버튼).
7. 테스트 `src/story/story.test.ts`: 챕터 id 유일·unlocks가 실제 장소/챕터를 가리킴·1장 scenes가 비어 있지 않음 / 기술·아이템 id 유일 / progress 직렬화 왕복 / 집중력 계산(휴식 → focusMax, 기술 사용 → 비용 차감, 0 미만 불가). package.json 테스트 목록에 추가.

## 2. 여정 지도 씬 (src/scenes/journey.ts)
- 세로 화면. 상단: day·소지금(원화 "120,000원")·압류 예고 "3,200만 원"(작게, 붉은 글자). 가운데: 장소 노드(이발소·집·편의점·목욕탕·시장·항구·당구장·호텔)를 **그림 없이** 원과 이름으로 세로 지그재그 배치. 열린 곳은 밝게, 잠긴 곳은 어둡게 + "N장에서 열림". 다음에 가야 할 곳에 금색 테두리와 작은 "▶".
- 노드 선택 → 그 장소의 행동 메뉴(모달 재사용): 이발소 = [대화(이야기 재생) / 대결(1장) / 연습 대결(무료)], 집 = [휴식 / 연습 대결 / 아버지 물건 조사(1장 상자 내용 글자로)], 편의점 = 잠김 안내.
- 휴식: focus = focusMax, day += 1, 저장. 간단한 "밤 → 아침" 전환(검은 막 400ms, 글자 "다음 날").
- 하단: 메뉴(소리·연출 줄이기·규칙·개발 정보·진행 초기화).

## 3. 집중력과 눈썰미 (TableScene 변경, 규칙 불변)
- TableScene은 `data: { chapterId?, opponent: OpponentProfile, practice: boolean }`를 받아 시작한다. 상대 이름·초상화·정책은 프로필에서. 시나리오 모드(개발용)는 그대로.
- 내 정보 패널에 **집중력 바**(가로 120, 현재/최대, 금색). 대결 시작 시 progress.focus를 읽고, 대결 중 소모는 메모리, 끝나면 저장.
- 기존 "다음 패 보기 1회" 버튼을 **기술 버튼**으로 바꾼다: 눈썰미(비용 20, 판당 2회, 더미 윗장 1장 공개). 집중력이 부족하거나 횟수를 다 쓰면 비활성. 동작은 지금의 peek과 같다(`s.peekUsed` 대신 횟수 카운터, 규칙 상태는 그대로). 기술을 아직 안 배웠으면(프롤로그·1장 대결) 버튼 자체가 없다.
- 결과창 버튼: practice면 [한 판 더 / 지도로], 챕터 대결이면 승리 시 [계속](→ after 장면 → 보상 → 지도), 패배 시 [한 판 더 / 지도로](1장은 패배 비용 없음).

## 4. 이야기 씬 (src/scenes/story.ts)
- Scene[]을 순서대로 보여준다. cut: 화면 가운데 큰 사각형(그림이 있으면 그림, 없으면 어두운 패널) + 아래 글자. line: 왼쪽 작은 초상화(있으면) + 이름 + 말풍선 글자. 터치/클릭으로 다음, 길게 누르면 빨리 넘김. 상단 "CHAPTER 01 · 머리부터 자르고 와라".
- 글자는 타자 효과 없이 한 번에(연출 줄이기와 무관하게 단순). 마지막 장면 뒤 콜백으로 다음 단계(대결 시작 / 보상 모달 / 지도).

## 5. 1장 흐름 연결
앱 시작 → progress 로드 → chapter가 'prologue'면 프롤로그 4컷 → 여정 지도(이발소만 열림, 금색) → 이발소 [대화] → 1장 before 장면(대식 대사) → 대결(장대식, beginner) → 승리 → after 장면(상자·사진·"패 좀 만졌다"·당부) → 보상 모달 "눈썰미를 배웠다" → progress: skills+눈썰미, places+집·편의점(편의점은 '잠김: 2장' 상태로 보이기만), chapter='ch2', 저장 → 지도.
패배 → "한 판 더" 즉시 재대결(before 장면 반복 없음) 또는 지도.
기존 main.ts의 인트로 모달(INTRO_MESSAGE, CHAPTER 상수)은 이 흐름으로 대체한다. 상단 띠의 챕터 제목은 현재 챕터 데이터에서 읽는다.
