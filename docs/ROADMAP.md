# 마지막 패 — 개발 로드맵 (2026-10-28 기준)

역할 분담: 기본 맞고 화면·연출은 기준작('고스톱대전')의 익숙한 문법을 재현한다. 스토리·스킬·성장·상대 캐릭터 같은 차별점은 소유자가 정한다.
코드 원칙: 규칙 계층(`src/game.ts`, `score.ts`, `cards.ts`, `ai.ts`, `beginner.ts`, `scenarios.ts`)은 완성 상태라 건드리지 않는다. 화면은 "계획 → 연출 → `applyTurn` 1회" 구조를 유지한 채 `src/ui/*`와 `main.ts`만 손본다.

현재 완성도(코드 확인 기준): 규칙 엔진 약 85% · 기본 대결 화면 약 45% · 스토리 제품 약 15%.

## B. 실제 플레이 확인 (소유자 + Cursor)
PC 브라우저와 휴대폰(같은 Wi-Fi, `npm.cmd run dev -- --host`)에서 한 판 끝까지 돌린다. 확인 목록:
잘림·겹침 / 터치 반응(손패·바닥 선택·모달) / 연출 끊김·너무 길거나 짧은 시간 / 효과음 타이밍 / 상대 턴 템포(`FX.think`) / 결과창 가독성.
발견한 문제는 "현상 → 기대"로 적어 Cursor에 넘기고, 수정은 `layout.ts` 수치와 `fx.ts`의 `FX` 값 위주로 한다.

## C. 긴 화면 대응
기준작은 1080×2340(19.5:9)을 꽉 채운다. 현재 720×1280 FIT은 긴 폰에서 위아래 검은 띠가 생긴다.
→ 디자인 폭 720 고정, 높이는 기기 비율에 맞춰 1280~1560으로 가변(`Phaser.Scale.FIT` + `REGIONS`를 높이 함수로). 안전 영역(노치·홈바) 여백. 터치 영역 최소 44px.

## D. 남은 규칙 (규칙 계층 수정이 필요한 유일한 단계)
첫뻑 보상 → 연속뻑 → 3뻑 자동 승리 → 총통(같은 월 4장) → 멍박(열끗 7장 이상) → 나가리 이월(선택). 각각 README 규칙표에 "확정" 행을 먼저 쓰고 테스트부터 추가한다. 선(先) 교대(진 사람이 다음 판 선)도 여기서.

## E. 상대 다양화
전략 정책(`ai.ts`)을 두 번째 상대로 실제 연결. 상대별 성격 파라미터(고/스톱 임계값, 초반 무작위 비율, 대사 세트)를 `character.ts` 한곳에서 관리. `npm.cmd run match`로 승률 목표(플레이어 65~75%) 확인.
