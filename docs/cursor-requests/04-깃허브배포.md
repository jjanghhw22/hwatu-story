# Cursor 요청 04 — GitHub 저장소 + GitHub Pages 자동 배포

목표: `hwatu-story` 폴더를 GitHub 저장소로 만들고, main에 push할 때마다 GitHub Actions가 빌드해 GitHub Pages로 배포되게 한다. 그러면 `https://<계정>.github.io/hwatu-story/` 주소를 누구에게나 보낼 수 있다.
저장소 루트는 `hwatu-story` 폴더다(상위 `hwatu-story-starter`의 사진·zip은 올리지 않는다).
게임 코드(src/*)는 바꾸지 않는다. index.html의 폰트 경로 한 곳만 상대 경로로 고친다.

## 사전 조건 (사용자가 직접)
- GitHub 계정. 없으면 https://github.com/signup 에서 만든다.
- `gh` CLI가 없으면 `winget install GitHub.cli` 후 터미널을 다시 연다.
- 터미널에서 `gh auth login` → GitHub.com → HTTPS → 브라우저로 로그인. 이 한 단계만 사람이 한다.

## 1. 저장소 파일 준비
1. `.gitignore` 생성:
```
node_modules/
dist/
.vite/
*.log
.DS_Store
Thumbs.db
```
2. `vite.config.ts` 생성(없음). Pages는 하위 경로(`/hwatu-story/`)에 올라가므로 base를 환경변수로 받는다. 로컬 dev·build는 지금처럼 `/`:
```ts
import { defineConfig } from 'vite';
export default defineConfig({
  base: process.env.VITE_BASE ?? '/',
  server: { host: '127.0.0.1' },
});
```
3. `index.html`의 `@font-face` 세 줄에서 `url("/assets/fonts/…")`를 `url("assets/fonts/…")`로 바꾼다(절대 경로는 하위 경로 배포에서 깨진다). 다른 내용은 그대로.
4. `package.json` scripts에 추가: `"build:pages": "tsc --noEmit && vite build"` (base는 워크플로가 VITE_BASE로 넘긴다). 기존 scripts는 그대로.
5. `src/ui/cardAssets.ts`와 `src/character.ts`의 자산 경로가 이미 상대(`assets/…`)인지 확인만 한다. 맞으면 손대지 않는다.

## 2. GitHub Actions 워크플로
`.github/workflows/pages.yml` 생성:
```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: pages
  cancel-in-progress: true
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm test
      - run: npm run build:pages
        env:
          VITE_BASE: /${{ github.event.repository.name }}/
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```
테스트가 실패하면 배포되지 않는다(의도).

## 3. 저장소 만들고 올리기 (hwatu-story 폴더에서)
```
git init -b main
git add .
git commit -m "v0.17 기본 화면 재조립·보정"
gh repo create hwatu-story --private --source=. --push
```
- 저장소는 **private**으로 만든다. GitHub Pages는 private 저장소에서는 유료 플랜이 필요하므로, Pages를 켜기 전에 아래 중 하나를 사용자에게 묻는다: (a) 저장소를 public으로 전환(코드가 공개됨. 화투 도안은 CC BY-SA라 공개에 문제 없음, THIRD_PARTY_NOTICES.md 포함) (b) private 유지하고 Pages는 포기하고 Netlify 사용. 사용자가 (a)를 고르면 `gh repo edit --visibility public --accept-visibility-change-consequences`.
- Pages 소스 설정: `gh api -X PUT repos/{owner}/hwatu-story/pages -f build_type=workflow` (이미 켜져 있으면 404/409가 날 수 있으니 그때는 `gh api repos/{owner}/hwatu-story/pages`로 상태만 확인). 안 되면 사용자에게 "GitHub → Settings → Pages → Source: GitHub Actions"를 눌러 달라고 안내한다.
- `git push`로 워크플로가 돌면 `gh run watch`로 끝까지 지켜보고, 성공하면 `gh api repos/{owner}/hwatu-story/pages --jq .html_url`로 주소를 받아 보고한다.

## 4. 확인·보고
- 로컬 `npm.cmd test`, `npm.cmd run build`가 여전히 통과하는지(기본 base `/`).
- 배포 주소를 PC 브라우저에서 열어 카드 그림·폰트·초상화가 404 없이 로드되는지 개발자 도구 Network 탭으로 확인(브라우저 자동화는 쓰지 않고, 사용자가 열어 보도록 안내해도 된다).
- README "Windows에서 실행" 아래에 "배포: main에 push하면 GitHub Pages로 자동 배포, 주소 …" 한 줄 추가.
- 보고: 저장소 주소, Pages 주소, 워크플로 실행 결과, 바꾼 파일 목록. 로그인·공개 전환처럼 사용자가 직접 한 단계는 따로 표시.

## 이후 흐름
버전이 바뀔 때마다 `git add . && git commit -m "v0.xx …" && git push` 한 번이면 1~2분 뒤 같은 주소가 갱신된다. 요청문마다 마지막 단계에 "커밋·push"를 넣을 것이다.
